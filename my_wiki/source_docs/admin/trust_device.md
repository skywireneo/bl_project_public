# Документация: Система доверенных устройств

## 1. Введение

**Доверенные устройства** — это механизм, который позволяет пользователям входить в систему без повторного ввода админского кода (второго фактора аутентификации) на устройствах, которым они доверяют.

**Основная цель:** Баланс между безопасностью и удобством. Пользователь один раз подтверждает, что устройство принадлежит ему, и в дальнейшем входит быстро, без лишних шагов.

---

## 2. Ключевые понятия

### 2.1. Два статуса устройства

В системе есть два разных статуса, которые важно не путать:

| Статус                    | Что означает                                                          | Как определяется                       |
| ------------------------- | --------------------------------------------------------------------- | -------------------------------------- |
| **Известное устройство**  | Система «узнала» устройство по его цифровому отпечатку (фингерпринту) | Автоматически при входе                |
| **Доверенное устройство** | Пользователь явно подтвердил, что доверяет этому устройству           | Только по явному действию пользователя |

**Важно:** Устройство может быть *известным*, но *не доверенным*. В этом случае при каждом входе всё равно потребуется админский код.

### 2.2. Что такое «отпечаток устройства» (фингерпринт)

Это уникальный идентификатор, который браузер формирует на основе:
- Версии браузера и ОС
- Разрешения экрана
- Установленных шрифтов
- Часового пояса
- Других параметров

**Важно понимать:**
- Отпечаток не идеален — он может измениться после обновления браузера
- Два разных устройства могут случайно иметь одинаковый отпечаток (редко, но возможно)
- Один и тот же браузер в режиме инкогнито будет иметь другой отпечаток

## 3. Жизненный цикл устройства

### 3.1. Первый вход пользователя

```
Пользователь вводит логин + пароль
        ↓
Сервер проверяет пароль
        ↓
Сервер проверяет: это стафф-пользователь?
        ↓ ДА
Сервер ищет устройство по отпечатку
        ↓
┌─────────────────────────────────────────────────────────────┐
│ Устройство не найдено ИЛИ найдено, но НЕ доверенное         │
│ → Требуется ввод админского кода                            │
│ → После успешного ввода → устройство автоматически          │
│   помечается как ДОВЕРЕННОЕ                                 │
└─────────────────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────────────────┐
│ Устройство найдено И ДОВЕРЕННОЕ                             │
│ → Админский код НЕ требуется                                │
│ → Пользователь входит сразу                                 │
└─────────────────────────────────────────────────────────────┘
```

### 3.2. Повторные входы

- **С доверенного устройства:** вход по логину + паролю, без админского кода
- **С недоверенного устройства:** вход по логину + паролю + админский код
- **По сид-фразе:** вход без админского кода, устройство автоматически становится доверенным

### 3.3. Удаление устройства

При удалении устройства:
1. Все активные сессии на этом устройстве немедленно завершаются
2. Устройство помечается как удалённое (soft delete)
3. При следующем входе с этого устройства оно будет считаться новым

## 4. Действия пользователя

### 4.1. Сделать устройство доверенным

**Когда доступно:** Устройство уже есть в списке, но не доверенное.

**Как работает:**
1. Пользователь нажимает кнопку «Сделать доверенным»
2. Открывается модалка с объяснением, зачем это нужно
3. **Обязательно** требуется ввод текущего пароля для подтверждения
4. После подтверждения устройство помечается как доверенное

**Зачем нужен пароль:** Защита от ситуации, когда злоумышленник получил кратковременный доступ к разблокированному экрану и пытается добавить своё устройство в доверенные.

### 4.2. Отозвать доверие

**Когда доступно:** Устройство помечено как доверенное.

**Как работает:**
1. Пользователь нажимает кнопку «Отозвать доверие»
2. Открывается модалка с предупреждением о последствиях
3. После подтверждения устройство теряет статус доверенного

**Важно:**
- Активные сессии **не завершаются** (в отличие от удаления)
- При следующем входе потребуется админский код
- Пароль для подтверждения **не требуется** (операция безопасная)

### 4.3. Переименовать устройство

**Зачем нужно:** Устройства по умолчанию получают технические названия вроде «Windows / Chrome». Пользователь может дать понятное имя, например «Рабочий ноутбук».

**Как работает:**
1. Пользователь нажимает «Переименовать»
2. Вводит своё название
3. Опционально включает чекбокс «Добавить информацию о браузере и модели»
4. Сохраняет

**Пример:**
- Пользователь ввёл: `Основной`
- С чекбоксом: `Основной (Chrome, MacBook Pro)`
- Без чекбокса: `Основной`

### 4.4. Удалить устройство

**Как работает:**
1. Пользователь нажимает «Удалить»
2. Открывается модалка с предупреждением
3. **Если устройство доверенное** — показывается дополнительное красное предупреждение о том, что для следующего входа потребуется админский код или сид-фраза
4. После подтверждения устройство удаляется, все сессии завершаются

## 5. Действия администратора

Администраторы (роли `DEVELOPER`, `TOP_LEVEL_DEVELOPER`, `TOP_LEVEL_ADMINISTRATOR`, `ADMINISTRATOR`) имеют расширенные возможности:

### 5.1. Просмотр устройств других пользователей

Администратор может просматривать список устройств любого пользователя через админ-панель.

### 5.2. Управление устройствами пользователей

Администратор может:
- Делать устройства пользователей доверенными
- Отзывать доверие
- Переименовывать устройства
- Удалять устройства пользователей

**Важно:** Все действия администратора логируются в системе аудита.

### 5.3. Просмотр реальных IP-адресов

Обычные пользователи видят **замаскированные** IP-адреса устройств (например, `192.168.*.*`).

Администраторы видят **реальные** IP-адреса, так как это необходимо для расследования инцидентов безопасности.

## 6. Безопасность

### 6.1. Защита от несанкционированного добавления в доверенные

**Сценарий угрозы:** Злоумышленник получил доступ к разблокированному компьютеру пользователя и хочет добавить своё устройство в доверенные, чтобы потом входить без админского кода.

**Защита:** Для установки доверия **обязательно** требуется ввод текущего пароля. Без пароля операцию выполнить невозможно.

### 6.2. Автоматический отзыв доверия

**Зачем нужно:** Если пользователь не пользовался устройством долгое время (например, старый ноутбук в шкафу), и это устройство было украдено, злоумышленник не сможет войти без админского кода.

**Как работает:**
- Раз в день запускается автоматический процесс
- Все устройства, неактивные более **30 дней**, автоматически теряют статус доверенного
- Пользователь получает уведомление (если настроено)

### 6.3. Защита при удалении доверенного устройства

При удалении доверенного устройства система показывает **дополнительное предупреждение**, чтобы пользователь осознавал последствия:
- Все сессии будут завершены
- Для следующего входа потребуется админский код или сид-фраза

### 6.4. Логирование всех действий

Все операции с устройствами (установка/отзыв доверия, переименование, удаление) логируются в системе. Это позволяет:
- Отследить подозрительную активность
- Расследовать инциденты безопасности
- Понять, кто и когда менял настройки устройств

## 7. Автоматические процессы

### 7.1. Автоматическая установка доверия

Устройство автоматически становится доверенным в следующих случаях:

| Ситуация                                   | Почему автоматически                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| Успешный вход по паролю + админский код    | Пользователь уже доказал, что владеет устройством, введя второй фактор |
| Успешный вход по сид-фразе                 | Сид-фраза сама по себе является криптостойким доказательством владения |
| Успешный вход по коду с другого устройства | Новое устройство авторизовано через уже доверенное                     |

### 7.2. Автоматический отзыв доверия (cron)

**Расписание:** Раз в день (настраивается администратором)

**Логика:**
```
Для каждого устройства:
  Если is_trusted = true
  И last_login_at > 30 дней назад
  → Установить is_trusted = false
```

**Важно:** Устройство **не удаляется**, только теряет статус доверенного. Оно остаётся в списке, и пользователь может снова сделать его доверенным.

### 7.3. Автоматическое удаление старых устройств

**Расписание:** Настраивается администратором

**Логика:**
- Устройства, помеченные как удалённые (`is_deleted = true`) и неактивные более 30 дней, удаляются физически
- API-устройства (специальные технические записи) удаляются через 1 час неактивности

## 9. Частые вопросы (FAQ)

### ❓ Почему устройство перестало быть доверенным, хотя я его не удалял?

**Ответ:** Скорее всего, сработал автоматический отзыв доверия. Если вы не пользовались устройством более 30 дней, система автоматически сняла с него доверие в целях безопасности. Вы можете снова сделать его доверенным через настройки.

### ❓ Я удалил устройство по ошибке. Можно ли его вернуть?

**Ответ:** Нет, удалённое устройство восстановить нельзя. При следующем входе с этого устройства оно будет считаться новым, и потребуется админский код.

### ❓ Может ли одно устройство быть доверенным для двух разных пользователей?

**Ответ:** Нет. Доверие привязано к связке «пользователь + устройство». Одно и то же физическое устройство может быть доверенным для одного пользователя и не доверенным для другого.

### ❓ Что будет, если я отзову доверие у текущего устройства?

**Ответ:** Активная сессия продолжит работать. Но при следующем входе (или после выхода) потребуется админский код. Система показывает предупреждение, если это последнее доверенное устройство.

### ❓ Зачем нужна кнопка «Добавить информацию о браузере и модели» при переименовании?

**Ответ:** Для удобства идентификации. Если у вас несколько устройств с одинаковым названием (например, «Рабочий»), добавление информации о браузере и модели поможет отличить их друг от друга.

### ❓ Администратор может сделать моё устройство доверенным без моего ведома?

**Ответ:** Технически да, администратор имеет такие права. Однако все действия администратора логируются и могут быть проверены службой безопасности. В штатных сценариях администраторы не вмешиваются в доверенные устройства пользователей.

### ❓ Что произойдёт, если я изменю браузер или обновлю ОС?

**Ответ:** Отпечаток устройства может измениться. В этом случае система будет считать устройство новым, и потребуется повторный ввод админского кода. После этого устройство снова станет доверенным.

## 10. Глоссарий

| Термин                      | Определение                                                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Доверенное устройство**   | Устройство, которому пользователь явно доверяет и которое может входить без второго фактора                                    |
| **Известное устройство**    | Устройство, которое система узнала по отпечатку, но которому пользователь ещё не дал доверие                                   |
| **Фингерпринт (отпечаток)** | Уникальный идентификатор устройства, сформированный на основе параметров браузера и ОС                                         |
| **Админский код**           | Второй фактор аутентификации, статический секретный код, который требуется для входа с недоверенных устройств                  |
| **Сид-фраза**               | Криптографическая фраза из 12 слов, которая является альтернативным методом входа и автоматически делает устройство доверенным |
| **Soft delete**             | Метод удаления, при котором запись не удаляется физически, а помечается как удалённая                                          |
